# Task Cards

仅委派、并行、跨会话或高风险任务需要任务卡；普通单会话任务不建卡。复用当前会话或交接消息中的一份记录，直接更新；不另建重复台账，不默认附整段聊天。检查强度按[开发流程](development-workflow.md#验证选择)选择。

## 简短模板

保留下面六项，用短句和路径/符号引用填写。没有风险或阻碍时写“无”；可选补充项不适用时省略。

```text
目标 / 验收：可观察结果与关键场景
基线 / 所有者：起点 SHA；当前执行者；必要环境
范围：允许文件；禁止触碰的边界；有则写依赖与集成顺序
进度 / 下一步：已完成；接手后的第一个动作
检查：完整命令、退出结果、对应 SHA 或未提交 diff；尚需检查
风险 / 阻碍：未验证项、失败证据、停止条件
```

## 按需补充

- **跨设备**：分支、当前 SHA、已推送并核对的远端 SHA；未推送明确标“仅本地”。接收端按[跨设备协议](development-workflow.md#codex-与-zcode-跨设备协作)核对。
- **代码图谱证据**：使用的项目、证据层级、索引新鲜度、限定查询及分页状态、相关符号/路径、覆盖缺口和已读源码；无图谱依赖时省略。
- **缺陷修复**：最小复现或失败断言、已尝试方案和结果；同一失败两次修复未成功就停止盲试。
- **高风险**：不变量、失败/授权/兼容场景、明确禁止操作、所需 `verify:full` 和相关隔离 E2E/迁移检查。不能因模板缩短而省略。
- **独立并行工作**：各自独立分支/工作树和文件所有权，共享文件串行，声明集成顺序。接手者不覆盖其他人的修改。

## 示例

```text
目标 / 验收：文档内跳转链接可用；普通文档任务按风险矩阵检查
基线 / 所有者：<起点 SHA>；当前执行者
范围：docs/example.md；不改业务、发布或验证脚本
进度 / 下一步：修复链接；接手者核对最终 diff
检查：链接核对、npm run check:public-tree、git diff --check；记录退出结果及所查 diff
风险 / 阻碍：无；若需越过文件边界，先重新确认范围
```

交付只报告修改文件、测试结果和剩余风险；日志、截图等证据以引用提供，不复制无关背景。命令尚未完成时不得预填“通过”；空计划和 dry-run 不算验证。
