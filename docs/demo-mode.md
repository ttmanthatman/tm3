# 演示模式维护

演示模式是主程序的可选能力，不维护平行的“演示版”分支。默认关闭；关闭时服务端不注册演示路由，客户端不加载演示管理页面，也不会请求 GitHub 或下载演示包。

## 使用方式

只在专用演示站启用，不要在生产站启用：

```bash
npm run demo:enable
npm run demo:disable
```

命令会修改服务器 `.env` 中的 `DEMO_MODE`，并在找到配置的 PM2 应用时自动重启。也可在首次部署时设置 `DEMO_MODE=1`。

启用后，管理员进入“管理 → 数据与系统 → 演示模式”：

- “检查 GitHub 演示数据”只读取清单，不修改聊天室。
- “载入/复位演示数据”会下载并校验演示包，然后替换演示账号、频道、消息、互动、音乐和展示素材。
- 运维管理员账号、服务器密钥、DeepSeek 密钥和推送密钥不会被演示包覆盖。
- 相同版本优先使用服务器缓存；只有首次载入或数据版本变化时才重新下载。

复位是破坏性操作。首次启用前仍应保留可恢复的数据库和存储备份；不要把 `DEMO_MODE=1` 配到正式聊天室。

## 制作和发布演示包

先在隔离的演示数据库中整理公开、虚构的数据，再运行：

```bash
npm run demo:bundle
```

常用环境变量：

- `DATABASE_URL`：演示数据源，必填。
- `DEMO_DATASET_VERSION`：递增的数据版本。
- `DEMO_OPERATOR_USERNAME`：不写入演示包、复位时保留的管理员。
- `DEMO_APPEARANCE_DATABASE_URL`、`DEMO_APPEARANCE_STORAGE_ROOT`：可选的外观设置和素材来源。
- `DEMO_MIN_APP_VERSION`、`DEMO_MAX_APP_VERSION`：演示包兼容的程序版本范围。

输出目录 `output/demo-bundle/` 已被忽略，不提交大型数据文件。将 `demo-manifest.json` 和 `demo-bundle.tar.gz` 上传到 GitHub Release 的固定标签 `demo-data`；需要其他来源时，用服务器私有配置 `DEMO_MANIFEST_URL` 覆盖。

演示包只能包含虚构账号和公开展示内容。不得复制生产用户、聊天记录、API Key、数据库连接或推送密钥；复用壁纸、登录背景和音乐前要确认它们适合公开展示。

## 开发工作流

每次发布只问一句：**这次是否改变了可展示功能，或演示包的兼容性？**

| 触发情况 | 要做的事 |
| --- | --- |
| 普通修复、内部重构、无展示变化 | 不更新演示数据。 |
| 新增或改变消息类型、展示设置、媒体/AI 功能 | 同步检查导出、校验、复位代码及相关测试；必要时补一条示例内容。 |
| 演示内容过时，或本次版本包含上述变化 | 生成递增版本的演示包，发布两个 Release 资源，并在专用演示站复位一次。 |
| 数据库、文件存储、认证或密钥规则变化 | 额外检查兼容范围、路径/哈希校验、管理员与密钥保留规则，不直接沿用旧包。 |

发布演示包后只做以下验收：核对清单数量、执行一次复位、确认登录背景和聊天壁纸、抽查受影响的展示功能、确认测试消息能被再次复位清除，最后运行 `npm run verify:full`。
