# EPUB 阅读器完善计划与新对话交接

状态：待实施。本文是执行计划，不代表下列改造已经完成。

代码核对基线：`78e2c27`；编写时分支为 `codex/share-cards-bookmark-sticky`。新对话开始时必须重新检查工作树和最近提交，保留后续已有改动，不能直接重置到本基线。

## 1. 要交付的阅读体验

这次改造围绕五个结果展开：

1. 点开书后尽快看到目标文字；网络、解压、邻章准备可以并行，后台任务不能改变正在看的位置，也不能阻塞操作。
2. 鼠标滚轮、触摸惯性滚动、章节增删和图片迟到时，正文不突然跳到别处。
3. 进度、摘录、高亮、指定文字、笔记和聊天室分享共用可靠的原文地址；找不到时明确说明，不能假装定位成功。
4. Aa 的字号、行距、边距及阅读模式调整，在手机和桌面真实生效；调整后仍能继续读同一句，菜单和按钮始终可用，界面尊重设备安全区。
5. 为以后“选文录音 → ASR 对齐 → 句子播放”提供稳定的文字范围和定位接口。本次不开发录音、ASR、播放器、录音分享或公开录音。

完成的判断依据是用户看到的文字、真实交互和可复查的测试记录，不能仅凭 `scrollTop`、函数单测或页面截图宣布成功。

## 2. 技术方向：保留 EPUB，先完善内部阅读模型

继续用 EPUB 作为上传、保存和分发的原始格式，复用现有 Foliate、ZIP 加载、缓存及阅读器能力。EPUB 本身已经包含章节 XHTML、样式、资源和阅读顺序；目前证据指向加载流程、文字定位和异步布局协调的问题，不能据此判断必须更换文件格式。

本次增加的是与排版无关的规范文字模型和阅读器适配层，不要求预先将全站藏书转换为 HTML 文件。规范文字是定位用的数据，不是另存一套脱离原书的正文。

若测量确认解析成本仍是主要瓶颈，再单独评估后台预解析、章节索引或预生成资源。必须先展示收益、兼容成本、授权与缓存影响，不能以“改成 HTML 就会稳定”为前提重写整个阅读器。固定版式、扫描图书和超复杂排版需要单独识别能力边界，不能承诺支持和可重排 EPUB 相同的 Aa 效果。

## 3. 已核实的现状，以及尚未验证的部分

| 领域 | 当前已有能力 | 仍需解决的缺口 |
| --- | --- | --- |
| 打开与加载 | HTTP Range ZIP loader、整本私有缓存、相邻章节后台准备、章节 Promise 去重 | 未下载的书目前先整本下载，再次点击才打开；缺少统一优先级、并发预算和过期任务取消 |
| 连续滚动 | 原生外层滚动、离流准备 iframe、插入时几何锚点补偿、触摸静默门、ResizeObserver、销毁清理 | 已读 iframe 持续驻留；可见章节重排缺少文字锚点事务；不同异步入口还没有统一导航代次 |
| 定位 | `bookId + fraction + quote?`；按摘录匹配并高亮；分页与连续模式都有跳转入口 | 百分比依赖章节权重和几何，不能作为精确地址；重复句和推断错章时不可靠；缺版本和明确失败结果 |
| 选区与笔记 | 能读取选文、保存笔记、显示高亮和分享卡 | 选区未保留稳定原文偏移；高亮文字索引依赖当前 DOM 和可见性；共享 schema 严格，不能只给客户端增加字段 |
| 进度 | 本地数字、服务端 `BookProgress.fraction`、防抖保存 | 差值小会跳过保存；缺精确位置、跨设备冲突规则；远端进度优先不等于远端更新 |
| Aa | 主题、字号百分比、行距、边距、分页/连续切换 | 作者 CSS 可能压过设置；快速调整、字体和图片迟到未由同一事务保护；当前没有字体家族选择 |
| 移动界面 | 全局已有 visualViewport 高度变量与 safe-area 变量，界面与正文分层 | Aa 可能随滚动关闭；面板高度和顶栏偏移需适配；程序补偿滚动与真实用户输入需区分 |
| 缓存 | Service Worker 能把完整缓存切成 Range 响应 | 每个 Range 可能触发整文件条件更新，未见在途去重；并发是否放大下载/读取成本需要网络记录证明 |

前一轮已针对真实书籍分享入口，在本机 Chrome 验证了摘录可见、高亮及正文 iframe 上小幅原生滚轮的修复，并补充真实 EPUB 上传和聊天室分享链路的自动化测试。它是后续改造要保留的回归基线，不代表全部阅读器问题都已解决。

尚未完成的验证必须保留在交接中：

- 手机尺寸模拟和 Playwright WebKit 不等于 iPhone、Android 真机测试。
- 嵌入式浏览器曾出现重新打开书籍停在加载中、iframe 为 `about:blank`、blob 资源读取失败；实际 Chrome 能打开。原因尚未确定，需独立复现，不能归因于滚动，也不能因为 Chrome 通过而忽略。
- 用户此前选择“仅保留 GitHub 提交”，没有授权部署。线上页面不能默认视为当前 Git 提交；验证环境要记录实际代码版本。

## 4. 统一的原文地址与阅读视图

### 4.1 两种信息必须分开

- **原文地址**回答“哪一本书的哪一版、哪一章、哪几个字”，不随字体、屏幕宽度或滚动模式变化。
- **视图锚点**回答“这几个字现在位于阅读区域哪里”，供重排和布局补偿使用，是临时界面状态。

阅读百分比继续用于显示和拖动进度条，兼容旧数据；不能用它代替原文地址。章节标题和书名也不能充当唯一标识。

### 4.2 统一 Locator 契约

建议建立版本化的 `BookLocatorV1`，字段职责如下；最终命名应服从现有项目约定。

| 字段组 | 内容与约束 |
| --- | --- |
| 契约版本 | `version`，便于未来兼容升级 |
| 原书身份 | `bookId`、`publicationRevision`；后者标识同一原文件，例如服务端生成的文件摘要，不能使用书名或百分比代替 |
| 文本算法身份 | `textRevision`，固定规范文字算法版本 |
| 章节身份 | 规范化的 `sectionHref`；章节 index 仅作加速提示 |
| 精确范围 | 起止文字偏移，以及可用时的 EPUB CFI；进度使用单点，摘录/笔记使用范围 |
| 校验和恢复 | 原文摘录 `exact`、有限长度的 `prefix/suffix`；长选区只携带受控的校验片段，不能无限扩大消息 |
| 旧数据回退 | 可选 `fraction`，明确标记为粗略进度 |

现有 Foliate 已提供 CFI 生成/解析能力，应先验证并复用，不增加新的阅读器或定位依赖。CFI 只对同版原书、兼容的源结构有意义；它和文字偏移互为校验/恢复手段，不能宣称跨版本永久有效。

原文件摘要应在上传/导入或后台维护时计算和复用，不能为了生成定位地址，阻塞每次开书等待整本下载、哈希。旧书尚无可验证 revision 时，允许先阅读；内部临时地址不能伪装成已验证的跨设备永久地址。服务端元数据补齐归入独立的持久化阶段。

跨章节选区如受现有交互支持，使用有序的章节范围集合表示；不得把不同章节的 offset 拼成一个无法解释的数字。暂不支持的选择方式应有明确边界，不截断后静默保存。

### 4.3 可重现的规范文字与双向映射

以章节为单位建立规范文字，不为跳转到一章而同步解析全书。必须同时支持：

1. DOM Range → 原文范围地址。
2. 原文范围地址 → DOM Range → 定位、高亮、矩形。
3. 当前可见文字 → 视图锚点 → 重排后恢复。

规则必须版本化并有样例：空白折叠、块边界、跨内联标签、换行、中文标点、emoji、组合字符、ruby、脚注分别如何处理。选择 UTF-16 offset 以匹配浏览器 Range，并明确后台实现的换算规则；不能切到代理对中间，交互边界应尊重完整字素。

不得因 Aa、主题、媒体查询、动态隐藏、插入高亮或未来播放按钮而改变文字身份。正文和脚注的文本域要有固定语义规则，不能按当前 computedStyle 临时决定哪些字存在。由源内容生成的规范文字与实际显示 DOM 必须有可验证映射；无法可靠映射时返回失败，不能猜测。

高亮和附加控件继续优先采用 CSS Highlight 或独立装饰层，避免在正文包裹、拆分文本节点，破坏 CFI、选区和排版。装饰层不得参与文字索引、正文尺寸或用户选文。

### 4.4 一个解析器服务全部入口

进度恢复、笔记、摘录、指定文字、分享、目录后的定位，以及未来录音，均使用同一解析服务和两种渲染模式适配器。

解析顺序：同版精确地址并校验原文 → 同章文字与前后文恢复 → 有界的其他候选章节搜索 → 兼容旧百分比回退。目录的章节导航不强行伪造文字范围。

返回明确状态：`exact`、`recovered`、`approximate`、`ambiguous`、`revision-mismatch`、`not-found`。重复句不能任意挑一处并宣称精确命中；版本不符不能静默绑定到另一版书。存在歧义时提供候选上下文或提示，粗略回退也应说明。

首次打开目标需同时做到：文字进入约定阅读带、目标范围清晰高亮、读者开始滚动后不被后台任务拉回。不要以持续定时 `scrollIntoView` 保持高亮。

## 5. 加载与滚动：并行准备，受控提交

### 5.1 打开路径和后台加载

- 将“立即阅读”和“整本下载供离线使用”分开；一次点击即可开始打开目标章节，同时显示真实加载进度和可恢复错误。
- 先核对 Range 在服务端、ZIP 和缓存路径的实际行为。服务端忽略 Range 或压缩结构不适合随机读取时，应识别并合理回退，不能制造大量重复全文件请求。
- 请求调度优先级：当前导航目标 → 当前可见资源 → 接近阅读方向的邻章 → 反向邻章 → 非紧急索引/预取。
- 使用有上限的并发，初始预算可从 2–3 个章节准备任务试验，再按测量调整；并发数量不是验收目标。
- 同一资源/章节去重；过期导航取消或丢弃；共享资源用引用计数或等价生命周期管理，避免误释放正在显示的 blob URL。
- 登出、换用户、换书、关闭阅读器时处理取消与清理，维持现有账户隔离和私有缓存策略。
- 慢网、离线、鉴权失败、章节损坏要有明确结果；预取失败不弹出阻塞当前阅读的错误，也不能吞掉目标章节失败。

网络请求可以并发；解析、解压和离流排版应按主线程预算分批交错准备。当前 ZIP 配置禁用 Worker，布局也占用主线程，不能把同时启动 Promise 宣称为 CPU 并行。是否启用已有 Worker 能力由 P0 长任务与兼容性证据决定。进入正文滚动流的变更必须统一提交，后台加载不关闭菜单、不重置当前视图、不保存成新的阅读进度。

Service Worker 先测量。若确认缓存更新或切片放大开销，再提出最小修正及缓存兼容方案；仓库对 service-worker 文件有明确授权要求，本计划不自动授权修改。不能通过跳过鉴权、公开私有书籍资源或清空用户离线缓存提速。

### 5.2 单一布局事务

覆盖章节插入、卸载、上方尺寸改变、图片/字体迟到、Aa、旋转和阅读模式切换：

1. 捕获当前可见原文地址及其相对有效阅读区域的位置。
2. 标记导航/布局代次；准备阶段不改变用户当前正文。
3. 检查最新用户意图、滚动状态和生命周期，再提交几何变化。
4. 使用同一锚点恢复；处理字体就绪和后续图片尺寸变化，不无限等待所有远程资源。
5. 重新计算高亮与装饰矩形，完成后只记录真实阅读位置。

用户正在触摸或惯性滚动时，应尽量延迟会改变上方布局的提交，而不是停止所有后台加载或禁用滚动。用户已转向新位置时，旧事务必须失效，不能把视图拉回旧位置。

明确用户滚动、主动定位、布局补偿三种事件来源，避免补偿触发隐藏控制栏、关闭 Aa、保存错误进度或递归补偿。原生 scroll anchoring 与人工补偿只能有一个明确责任者，沿用并检验现有 `overflow-anchor` 策略，不叠加两套修正。

### 5.3 有边界的章节驻留

先稳定锚点，再引入内存窗口。连续读很长的书时，iframe、事件监听器、规范文字索引和 blob 资源不能无限增长。

按照可见范围、滚动方向和内存预算保留必要章节；远章退出时保留足够的布局占位和逻辑地址。P3 开始时明确记录已挂载章节数、准备任务数、索引缓存的具体预算和淘汰规则，结合超长单章校准，而非仅按章节数量判断内存。

占位高度与字号、行距、边距和视口签名关联；重排后不能沿用错误的旧高度。远章允许暂用估算，恢复时重新测量并由锚点事务保护，不能为计算全书新高度重新加载所有远章。选区、高亮操作和当前目标涉及的章节应暂时受保护。

不要直接移除上方章节，也不要将“虚拟化全书”作为第一步。以长书往返、重排和跳转回归证明收益与稳定性后再扩大窗口策略。

## 6. Aa 与移动端界面

### 6.1 用户排版规则

字号、行距、正文边距必须由用户设置可靠控制；主题不改变文字地址。对可重排 EPUB 制定受控覆盖规则：能覆盖作者固定字号和过强正文样式，同时保留标题层级、强调、诗歌换行、列表、表格、图片和脚注语义。不能全局把所有元素强制成同一字号。

识别固定版式 EPUB，保留适合它的显示路径或明确提示能力限制；不对固定版式图文书强制应用通用正文重排，也不按可重排书的 Aa 门槛宣称通过。

当前没有字体家族选择。本次优先完成既有控制项；若增加字体选择，先复用项目可用字体并验证缺字回退、加载失败、字体就绪后的锚点恢复，不默认新增外部字体服务或依赖。

设置持久化需有版本、范围验证和兼容默认值。快速连续调整采用最新设置生效，过时事务不回写；滑杆可适当合并更新，但可见反馈应及时。分页与连续模式共享同一设置语义及原文地址，不能切换后只靠百分比找回。

### 6.2 界面与正文独立

- 复用项目已有 `--app-height`、visualViewport 和安全区变量，定义一套明确的 safe-area 责任，避免重复扣减或漏算。
- 顶栏、底栏、Aa、目录和笔记操作处于宿主界面层；正文缩放和作者样式不影响按钮位置、字号或命中区域。
- 面板位置依据实际工具栏/可用视口测量，避免仅靠固定 `54px` 假设。窄屏、横屏和软键盘弹起时，面板内部可滚动且能关闭。
- Aa 打开期间，设置引发的补偿滚动不关闭面板；正文点击显示/隐藏控制栏不能吞掉选文、链接和按钮点击。
- 确认透明/隐藏层不会拦截点击；菜单开关、焦点、Escape、触控和返回路径一致。关键触控目标至少 44 CSS px。
- 检查顶部状态栏/刘海/电池区域、底部手势区、浏览器地址栏伸缩和 PWA 独立模式；不能只凭桌面截图验收。

## 7. 持久化与旧数据兼容

这是独立的 shared/server/database 阶段，不能夹在客户端重排修复中未经核对直接上线。

1. 新笔记和新分享可携带可选 locator；旧 `quote/chapter/fraction`、旧 HTML 消息和旧链接继续可读。更新所有严格 schema、DTO、服务端验证、客户端序列化及分享快照解析，不能只改一端。仍在运行的旧客户端可能拒绝未知字段，应通过明确的契约版本或响应投影维持旧格式；不能仅给新 schema 增加 optional 字段就宣称双向兼容。
2. 笔记目前存于账户/图书隔离的 Setting JSON，并非独立的 Prisma BookNote 表。可增量兼容字段，不做无必要的整体存储重构；不在这里另建未来音频库。
3. 精确阅读进度要跨设备保存，需为 `BookProgress` 设计可选 locator、版本及更新修订信息。继续保留 fraction 兼容旧客户端；不能将正式进度随意塞入另一份 Setting 绕过迁移。旧客户端只写 fraction 时，必须在同一事务使旧 locator 失效或降为粗略状态，并更新服务端修订，避免新百分比搭配旧精确地址；新客户端不能使用与当前修订不一致的 locator。
4. 规定保存与冲突规则：区分主动阅读和后台补偿；关闭/切书时尽力提交最后位置；离线进度有待同步状态；以服务端修订号检测冲突，不单靠客户端时钟。自动恢复不得覆盖正在读的新位置；不能简单取更大百分比，因为回读也是有效进度。
5. 原文件替换或文本规则升级须识别 revision 不符，保留旧位置及恢复结果；不批量破坏性重绑所有旧笔记。
6. 持久化字段/索引方案需先形成具体可评审差异，再按仓库规则取得缺失授权。涉及 Prisma 必须新增真实 migration，在一次性数据库验证；不修改已提交迁移，不对保留环境 `db push`。

客户端统一定位完成并不等于跨设备精确进度完成。只有这一阶段的数据写入、读取、离线与冲突回归通过后，才可以宣称闭环。

## 8. 为未来录音功能打的地基

本次交付到以下接口与合成样例为止：

- 选文得到可序列化的原文范围，并能读取与该范围对应的规范文字。
- 选文内的 `[start, end)` 子范围能映射为原书句子范围，支持定位、高亮和获取矩形；句子以地址标识，不以当前分页、行号或句子序号标识。
- 记录文本算法版本和原书版本；同一规范文字输入在客户端和未来后台有可重现定义。
- 为定位、高亮和将来的句旁播放控件提供装饰接口。控件不得参与正文索引或改变行高；当前不显示空的播放按钮。
- 用合成数据验证“选文 → 多个句子子范围 → 重排后仍回到原句”，以及无效/越界范围被拒绝。

未来的处理链路应是：选文范围和原书版本 → 录音及 ASR transcript/时间戳 → 独立文本对齐 → 原文子范围与音频时间段的映射 → 分享/播放。

ASR 文本可能漏词、重读、替换词和改标点，不能把 transcript 的字符位置或按句号分割的结果直接当作原书 offset。未来对齐结果需表达一对多、多对一、未对齐、可信度和人工修正，并记录音频毫秒时间段、对齐版本和来源。

本次只写清该边界，不实现对齐算法、录音表、ASR 表、上传接口、麦克风权限、后台任务、公开授权或聊天室音频消息。定位地址本身不授予阅读或音频访问权限；未来分享录音也不能顺带公开私人笔记。

## 9. 实施顺序与阶段完成条件

每阶段保持可评审、可回退；实现时补充短任务卡，记录实际环境、改动范围和证据。不要先大拆文件再找问题。

| 阶段 | 工作 | 可交付与退出条件 |
| --- | --- | --- |
| P0：复现与基线 | 核对实际版本；记录冷/热/离线开书、原生滚轮、Aa、真实书和嵌入式浏览器空白打开问题 | 可重复步骤、网络/布局时间线、书籍规模与设备条件；区分已证实原因和待验证假设。先为关键故障建立会失败的回归 |
| P1：文字地址 | 规范文字、DOM 双向映射、版本化 locator、CFI 适配、解析状态、旧数据兼容入口 | 两种模式对同一句生成/解析一致地址；重复句不误认；字体变化不改变地址；现有分享链路仍通过 |
| P2：布局事务 | 统一导航代次、文字锚点捕获/恢复、滚动来源、延迟插入与尺寸更新 | 鼠标/触摸、前章迟到、图片/字体迟到、快速跳转、关闭中加载均不被旧任务拉回；复用已修复逻辑 |
| P3：加载与驻留 | 一次点击开书、请求优先级/并发/去重/取消、渐进索引、受控章节窗口 | 目标文字优先出现；后台预取不改变位置；长书资源驻留有上限；离线和账户隔离不退化。SW 的必要改动另列授权范围 |
| P4：Aa 与界面 | 受控正文样式、同一锚点重排、设置状态、面板布局、安全区和点击层级 | 字号/行距/边距实际生效；极值、连续操作、旋转与键盘下同一句仍在可阅读区域，菜单和按钮可用 |
| P5：持久化闭环 | 共享契约、笔记/分享可选 locator、精确进度与冲突规则、必要元数据/迁移 | 旧数据继续读取，新地址重开与跨设备恢复，版本不符和离线冲突可解释；迁移及权限检查通过 |
| P6：未来接口与综合验收 | 句子子范围合成样例、装饰接口边界、交叉回归、性能对比、真实设备 | 五项目标的证据完整；明确哪些设备未测；没有悄悄增加录音/公开分享功能 |

P1/P2 为后续重排和加载优化的基础。P3 的网络测量可与前期只读诊断并行；P5 可先设计契约，但修改 server/shared/schema 应单独形成完整任务。不要在核心锚点尚不稳定时加入复杂虚拟化。

若两次修复同一失败仍未解决，应停止盲目补丁，提交最小复现、假设和下一步诊断。不能以加长等待、削弱断言或吞异常绕过故障。

## 10. 验收矩阵

### 10.1 书籍和场景

保留可公开的合成 EPUB 作为自动化夹具；获准的真实书仅在本地验证，不提交版权文件、私人消息或截图。

至少覆盖：长篇多章节、短章节和超长章节混合、含图片且尺寸迟到、固定字号/强作者 CSS、固定版式的能力边界、中文与英文、重复句、跨标签/跨段落、emoji/ruby/脚注、损坏资源、首次下载、完整缓存、慢网与断网。大书规模和测试设备须记录，不能用三章等高文档代表所有场景。

### 10.2 可以直接核查的门槛

| 目标 | 验收方法与门槛 |
| --- | --- |
| 后台布局不跳 | 无用户输入时，跟踪同一文字锚点的屏幕坐标；上方插入/卸载/迟到尺寸更新后偏移原则上 ≤ 2 CSS px，且无闪回其他章节。边界例外须解释并记录 |
| 滚轮稳定 | 指针放在真实正文 iframe 上发送小幅正/反滚轮；远离边界时位移方向和幅度符合原生行为，无额外数百/数千像素跳跃；自动化可对非平滑桌面输入采用约 2 px 容差 |
| 触摸稳定 | 真机测试拖动、按住期间章节完成、松手惯性、反向滚动；没有程序强拉回或章节闪换。不能用桌面滚轮结果代替 |
| 位置准确 | 进度、摘录、笔记、分享及指定范围命中相同原文；重复句用上下文区分；明确显示粗略/歧义/失败状态；错误版本不静默命中 |
| 重排保持阅读 | Aa、模式切换、旋转后仍是同一文字锚点，并保留在约定阅读带，目标偏差不超过约一行；变化后的坐标不能用旧像素高度硬算 |
| Aa 忠实 | 核对实际字号、行距及内容边界；移动/桌面、最小/默认/最大值、强作者 CSS 都生效，标题/诗歌/图片没有被破坏 |
| 控件可靠 | Aa 打开连续调整不自行消失；菜单、关闭、目录、选文/笔记按钮能真实点击；检查命中元素和遮挡，非只检查可见样式 |
| 安全区 | 真机竖横屏、地址栏变化、软键盘和支持的 PWA 模式下，顶部不盖住状态栏/电池，底部不被手势区吞没，面板可滚动关闭 |
| 生命周期 | 快速 A→B→C 跳转只保留最新意图；关闭/换书/登出后没有迟到提交、无效 blob 使用或旧用户资源泄漏；嵌入式浏览器重复开关书完成验证 |
| 长书资源 | 固定设备连续浏览至少 100 章并多次往返，记录 iframe、索引、监听器、blob 和内存趋势；驻留量受预算控制，不能随已读章节无限增长 |
| 兼容与同步 | 旧链接/HTML 消息/笔记仍可读；旧格式进度写入后新客户端重开不恢复陈旧 locator；离线重开、同步失败重试、两个设备先后/同时更新、回读旧章都符合冲突规则 |
| 录音基础 | 合成选文的多个子范围经重排仍定位原句；无效 offset/版本被拒绝；没有真实录音或 ASR 依赖 |

定位“约定阅读带”建议以有效正文视口的上部约三分之一为默认目标，顶部扣除工具栏和安全区。分页模式以目标所在页及明确高亮验收，不机械要求同一 y 坐标。

### 10.3 性能测量

P0 固定一组设备、书籍和网络条件，冷启动、完整缓存热启动、离线分别计时，记录首次可操作、目标文字可读、位置稳定、网络请求/传输量和主线程长任务。稳定性修复前后使用同一条件，分清下载时间与解析/布局时间。

建议初始产品目标：中等规模已缓存书的目标文字可读 p95 ≤ 2 秒；Aa 可见反馈约 150 ms 内；稳定阅读期间避免超过 100 ms 的主线程长任务。每项至少取足够样本，p95 建议 20 次以上，记录设备和方差。若基线证明目标不适用，先提出有数据的调整，不事后静默放宽。

冷启动按固定书籍大小和网络吞吐制定下载预算，再单列解析/定位开销，不承诺任意大书“两秒打开”。前台目标加载不能被预取明显拖慢；并发优化必须展示瀑布和首屏结果，不能只报告请求同时发出了。

### 10.4 平台与组合流程

- 自动化：Chromium 桌面宽度至少 1280；手机宽度 360/390；WebKit 移动尺寸；继续保留现有分享卡中等宽度场景。
- 真实设备：桌面 Chrome、iPhone Safari、Android Chrome；项目声明支持的嵌入式浏览器；PWA 若在支持范围内单列。拿不到真机时明确列为未验证，不能用模拟器替代声明通过。
- 必测组合：聊天室分享精确跳转 → 小幅滚轮/触摸 → Aa 连续极值 → 字体/图片完成 → 旋转 → 继续滚动 → 关闭 → 从笔记或分享重开。
- 第二组组合：慢网快速切换目标 → 关闭阅读器 → 重开另一书 → 离线恢复 → 恢复联网；检查旧任务、缓存账户边界和最后阅读进度。
