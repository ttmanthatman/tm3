# 逐字手写 P0 交互原型

本目录是独立静态页面。**发送只在本页模拟**：没有账号、网络请求、数据库或刷新后的草稿恢复。关闭弹窗会保留当前页面内的草稿；刷新会重置。

## 启动

在仓库根目录运行：

```sh
python3 -m http.server 8765 --directory prototype
```

浏览器打开 <http://127.0.0.1:8765/handwriting/>。无需安装依赖。通过首页按钮或模拟输入框的“更多 → 手写”打开弹窗。

## 试写流程

1. 在方格写第一个字，点“完成此字”，再写第二个字；抬笔或停顿不会自动换字。
2. 点已完成字格可删除整个字。当前字格支持“撤销一笔”和“清空当前字”；“清空全部”需要确认。
3. 点“逐笔播放”看发送前预览。直接点“发送给收件人”也会包含当前尚未点“完成此字”的字。
4. 模拟会话只显示笔迹；长按手写消息会出现“重播”。键盘可聚焦消息后按 Enter、空格或菜单键打开。

单点笔画绘制为圆点；画板捕获单个活动指针，越界坐标夹在字格边界内；`pointercancel` 保留已采集笔迹。旋转/缩放从坐标重绘，字格尺寸不会进入数据。原型设 30 字、6000 点和 128 KiB 发送预算；超限会留在编辑界面给出提示。这里只演示交互与数据量，不代表生产协议已经冻结。

笔画粗细由相邻轨迹点的距离和时间差推算：移动慢时加宽，移动快时收窄，宽度逐点平滑，最终绘制与重播共用同一宽度序列。浏览器支持时读取合并的指针事件，以保留更密的轨迹；不支持时照常使用普通 `pointermove`。这是一种速度模拟，不能代替真实压感、笔锋方向或毛笔物理模型。设计参考：[perfect-freehand 的速度模拟参数](https://github.com/steveruizok/perfect-freehand/blob/main/packages/perfect-freehand/src/types.ts)、[W3C Pointer Events 合并事件说明](https://www.w3.org/TR/pointerevents/#coalesced-events)。

`samples.js` 生成可复现的 2/10/30 字合成笔迹，每字 3 或 4 笔、6 或 8 点。这些合成线条不是中文真人书写样本。页面显示其点数和完整 payload JSON 字节数，方便与实际手写消息对比。

| 合成样本 | 笔数 | 点数 | UTF-8 JSON | 外观 |
| --- | ---: | ---: | ---: | --- |
| 2 字 | 7 | 14 | 387 字节 | 两格交替线条 |
| 10 字 | 35 | 70 | 1,739 字节 | 两格线条重复五次 |
| 30 字 | 105 | 210 | 5,119 字节 | 两格线条重复十五次，窄屏自动换行 |

`evidence/` 中的截图记录最初版本的布局；当前版本以运行页面为准。

## 任务边界

- 起点：`502b0b7`，Node `v22.22.2`；`docs/handwriting-implementation-plan.md` 是已有的未跟踪用户文件。
- 本卡只修改 `prototype/handwriting/`。没有改生产 `src/`、Prisma、依赖、版本或发布文件。
- 下一步是用户实际试写并确认控件位置与手感，再由 S0 冻结共享协议。

## 验证记录

最初版本已用 Chromium 在 360×800、390×844、1280×800 和旋转模拟视口 800×360 检查。本次改动另以 WebKit 模拟 iPhone 检查了单击完成、手机画板尺寸、裸笔迹消息和长按菜单。原型验收不等同生产链路验收；iOS 真机的手指、横竖屏和后台行为需要在设备上单独试写。
